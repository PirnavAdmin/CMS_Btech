# Academic year scope: diagnosis and verification

The live ModulePermissionMiddleware reads the active account, user_roles and roles on each request. It normalizes role_code and bypasses permissions only for an active SUPER_ADMIN. For non-super users it requires a persisted college assignment and the appropriate academic_years permission, then rejects a different query/body college. It emits the reported 403 before the controller runs. A valid SUPER_ADMIN in the provided SQL dump would bypass this 403; the dump alone cannot establish the identity or JWT used in the reported request, or whether the running server matches these sources.

The dump has active SUPER_ADMIN role ID 1 assigned to user ID 1, and COLLEGE_ADMIN role ID 2 assigned to user IDs 2 and 3. All three users have users.college_id 1. No account assignment was changed because the failing identity and intended assignment were not provided. Existing tokens and current database state must be checked in the deployed environment.

The controller now consumes the middleware's verified live role/college snapshot. It no longer trusts an old elevated role claim or an obsolete college claim for authorization. JWT creation and middleware share CanonicalRoleCode; raw and legacy claims are retained for compatibility. Repository methods always receive the resolved college and filter their rows by it; the repository does not independently infer a user role. Scope is never silently changed when a different college is explicitly requested.

Contract: Super Admin supplies a positive existing collegeId in query or, for create/edit/generate, body. If supplied in both, values must agree. College-scoped accounts may omit it and use their current assigned college. A College Admin may also use an explicitly mapped college when active and permitted; other explicit different values are forbidden. Academic-year permissions are required for non-super users. Query/body mismatch for a Super Admin is 400; a scoped user's explicit cross-college value can be rejected earlier with 403. Record-by-ID queries are scoped to the resolved college.
