# Academic-year access for explicitly mapped College Admins

A College Admin with an active, Super Admin-granted college_user_mappings row can now manage academic years for the mapped college, subject to its academic_years module permission. The middleware joins college_user_mappings.college_setting_id to college_settings.college_id; it does not treat the setting ID as the college ID. Inactive/removed mappings, inactive settings or colleges, and other roles cannot use this access. Other APIs retain their existing scope policy. The academic-year controller consumes the same authorized scope. Query/body disagreement is still rejected. A college creation does not automatically grant or transfer administrative access.

For an existing college, a Super Admin may use the existing POST /api/v1/super-admin/college-mappings with {"userId": <admin user id>, "collegeSettingId": <college setting id>}; verify the college_settings row is active and references the intended college. This is a privileged administrative grant; do not create a mapping unless the admin is authorized. No data was changed by this ZIP. The assigned user's active role and academic_years permissions for that selected college must also allow the requested action.
