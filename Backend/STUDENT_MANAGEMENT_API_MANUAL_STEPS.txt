STUDENT MANAGEMENT APIs - MANUAL SETUP AND TESTING
==================================================

TASK COMPLETED
--------------
The project includes these student-master APIs:

1. GET   /api/v1/students
   Student list with pagination and optional filters.

2. GET   /api/v1/students/{studentId}
   Complete details for one student-master record.

3. GET   /api/v1/students/search
   Search by student code, full name, email, or mobile.

4. POST  /api/v1/students
   Create a student-master record.

5. PUT   /api/v1/students/{studentId}
   Edit a student-master record.

6. PATCH /api/v1/students/{studentId}/status
   Activate or deactivate a student-master record.

IMPORTANT DATABASE RULE
-----------------------
This implementation does not use EF Core migrations.
Do not run Add-Migration or Update-Database.
Use MySQL Workbench and run the SQL files manually.


PART A - DATABASE SETUP
=======================

STEP 1 - Open MySQL Workbench
-----------------------------
Connect to the local MySQL 8 server.


STEP 2 - Import the supplied database dump
------------------------------------------
If cms_btech is not already imported:

1. Open Server > Data Import.
2. Choose Import from Self-Contained File.
3. Select:
   Database/CMS_BTech_Database.sql
4. Create or select the cms_btech schema.
5. Start Import.

If the supplied dump is already imported and the students table is present,
do not import it again.


STEP 3 - Confirm the existing students table
--------------------------------------------
Run:

USE cms_btech;
DESCRIBE students;
SELECT * FROM students ORDER BY student_id;

The supplied dump already contains the students table and sample records.
No table migration is required.


STEP 4 - Install only the student stored procedures
---------------------------------------------------
Open and execute this complete file in MySQL Workbench:

Database/StudentManagement/StudentManagementStoredProcedures.sql

Execute the entire file, including DELIMITER statements.


STEP 5 - Verify the stored procedures
-------------------------------------
Run:

SHOW PROCEDURE STATUS
WHERE Db = 'cms_btech'
  AND Name LIKE 'sp_student_%';

You should see:

sp_student_get_all
sp_student_search
sp_student_get_by_id
sp_student_code_exists
sp_student_validate_references
sp_student_create
sp_student_update
sp_student_update_status

Test the read procedures:

CALL sp_student_get_all(NULL, NULL, NULL, NULL, NULL, 1, 20);
CALL sp_student_search('STU', NULL, NULL, NULL, NULL, NULL, 1, 20);
CALL sp_student_get_by_id(1);


STEP 5A - Optional direct stored-procedure tests
------------------------------------------------
These calls prove that the APIs are backed by working stored procedures.

Validate college, academic year, course, and branch IDs:

CALL sp_student_validate_references(1, 2, 1, 1);

Check whether a student code already exists:

CALL sp_student_code_exists('STU004', NULL);

Create a student directly through the stored procedure:

CALL sp_student_create(
    1,
    'STU004',
    'Meera Rao',
    'Female',
    '2005-07-18',
    'meera.rao@example.com',
    '9000000004',
    'A+',
    'Hyderabad, Telangana',
    1,
    1,
    2,
    1,
    1
);

The returned row contains the new student_id. Use that ID in the next two
calls. The example below uses 4 because the supplied dump starts with IDs 1-3.

Edit a student directly through the stored procedure:

CALL sp_student_update(
    4,
    1,
    'STU004',
    'Meera Rao Updated',
    'Female',
    '2005-07-18',
    'meera.updated@example.com',
    '9000000004',
    'A+',
    'Secunderabad, Telangana',
    1,
    1,
    2,
    1,
    1
);

Change status directly through the stored procedure:

CALL sp_student_update_status(4, 0, 1);
CALL sp_student_update_status(4, 1, 1);


PART B - BACKEND SETUP
======================

STEP 6 - Configure the connection string
----------------------------------------
Open appsettings.json and set the local MySQL password:

"DefaultConnection":
"server=localhost;port=3306;database=cms_btech;user=root;password=YOUR_PASSWORD;"

Do not change the database name unless the dump was imported into a different
schema. If the schema name changes, also update the USE statement in the
student stored-procedure file before executing it.


STEP 7 - Open and run the backend
---------------------------------
Visual Studio:

1. Open BTech.csproj or BTech.slnx.
2. Restore NuGet packages.
3. Build the solution.
4. Run the BTech project.
5. Open the Swagger URL shown in the console/browser.

Command line alternative:

dotnet restore
dotnet build
dotnet run

Again, do not run any EF Core migration command.


PART C - SWAGGER AUTHORIZATION
==============================

STEP 8 - Log in
---------------
In Swagger, run:

POST /api/v1/auth/login

Example body:

{
  "loginId": "YOUR_LOGIN_ID",
  "password": "YOUR_PASSWORD",
  "rememberMe": false
}

Copy the access token returned by the API.


STEP 9 - Authorize Swagger
--------------------------
1. Click Authorize.
2. Paste the JWT access token.
3. Click Authorize and Close.

All six student APIs require a valid JWT.


PART D - TEST ALL SIX APIs
==========================

STEP 10 - Student list
----------------------
GET /api/v1/students?pageNumber=1&pageSize=20

Optional filters:

status=1
collegeId=1
courseId=1
branchId=1
academicYearId=2

Combined example:

GET /api/v1/students?status=1&collegeId=1&courseId=1&branchId=1&academicYearId=2&pageNumber=1&pageSize=20

Expected result: HTTP 200 with items, pageNumber, pageSize, totalRecords,
and totalPages.


STEP 11 - Student details
-------------------------
GET /api/v1/students/1

Expected result: HTTP 200 for an existing record or HTTP 404 when the student
does not exist.


STEP 12 - Search students
-------------------------
Search by code, full name, email, or mobile:

GET /api/v1/students/search?query=STU&pageNumber=1&pageSize=20

Filter example:

GET /api/v1/students/search?query=Aarav&status=1&collegeId=1&pageNumber=1&pageSize=20

The search query must contain at least two characters.


STEP 13 - Create a student
--------------------------
POST /api/v1/students

Example body compatible with the supplied dump:

{
  "collegeId": 1,
  "studentCode": "STU004",
  "fullName": "Meera Rao",
  "gender": "Female",
  "dateOfBirth": "2005-07-18",
  "email": "meera.rao@example.com",
  "mobile": "9000000004",
  "bloodGroup": "A+",
  "address": "Hyderabad, Telangana",
  "courseId": 1,
  "branchId": 1,
  "academicYearId": 2,
  "status": 1
}

Expected result: HTTP 201 with the new studentId.

The API validates that:

- studentCode is unique;
- CollegeId and AcademicYearId exist;
- CourseId belongs to CollegeId;
- BranchId belongs to CourseId;
- status is 0 or 1;
- dateOfBirth is not in the future.


STEP 14 - Edit a student
------------------------
Use the studentId returned by create:

PUT /api/v1/students/4

Example body:

{
  "collegeId": 1,
  "studentCode": "STU004",
  "fullName": "Meera Rao Updated",
  "gender": "Female",
  "dateOfBirth": "2005-07-18",
  "email": "meera.updated@example.com",
  "mobile": "9000000004",
  "bloodGroup": "A+",
  "address": "Secunderabad, Telangana",
  "courseId": 1,
  "branchId": 1,
  "academicYearId": 2,
  "status": 1
}

Expected result: HTTP 200 and the updated record.


STEP 15 - Change student status
-------------------------------
Deactivate:

PATCH /api/v1/students/4/status

{
  "status": 0
}

Activate again:

PATCH /api/v1/students/4/status

{
  "status": 1
}

The API also accepts "active" and "inactive" for compatibility with the
current frontend status format.


STEP 16 - Final database verification
-------------------------------------
Run in MySQL Workbench:

SELECT
    student_id,
    college_id,
    student_code,
    full_name,
    course_id,
    branch_id,
    academic_year_id,
    status,
    created_at,
    updated_at
FROM students
ORDER BY student_id DESC;


EXPECTED HTTP STATUS CODES
==========================

200 - List, details, search, edit, or status update succeeded.
201 - Student created successfully.
400 - Request data or related IDs are invalid.
401 - JWT is missing, expired, or invalid.
404 - Student was not found.
409 - Student code already exists or a database business rule failed.
